# تقرير تحسين وأمان قواعد البيانات (Database Security & Optimization Report)
**المشروع:** نظام إدارة الكهرباء الذكي (SEMS)  
**الهدف:** تأمين محرك PostgreSQL وتحسين سرعة الاستعلامات  

---

## 1. أمان قواعد البيانات وحماية البيانات الحساسة

### أ. التشفير في السكون (Encryption at Rest)
* **المشكلة:** البيانات المخزنة في جداول المشتركين (`customers`) مثل الأسماء، الهويات الوطنية، وأرقام الهواتف تحفظ كنصوص واضحة.
* **التوصية:**
  - استخدام إضافة **pgcrypto** المدمجة في PostgreSQL لتشفير الحقول شديدة الحساسية (مثل الأرقام الوطنية وعناوين المشتركين الدقيقة) باستخدام تشفير AES.
  - *مثال للاستخدام:*
    ```sql
    CREATE EXTENSION IF NOT EXISTS pgcrypto;
    -- تشفير القيمة عند الإدخال
    INSERT INTO customers (national_id) VALUES (pgp_sym_encrypt('1234567890', 'encryption_key'));
    ```

### ب. تشفير الاتصالات (SSL/TLS Connection)
* **الوضع الحالي:** يتصل الباكيند بقاعدة البيانات عبر منفذ `5432` بدون تفعيل إلزامي لتشفير الاتصالات.
* **التوصية:** تعديل ملف إعدادات PostgreSQL (`postgresql.conf` و `pg_hba.conf`) لفرض تشفير SSL على كافة الاتصالات الواردة لمنع هجمات التنصت الداخلي على الشبكة:
  ```
  ssl = on
  ssl_cert_file = 'server.crt'
  ssl_key_file = 'server.key'
  ```

## 2. مراجعة وتعديل سياسة النسخ الاحتياطي (Backup Strategy)
يحتوي مجلد `scripts/backup_db.sh` على سكربت نسخ احتياطي جيد يقوم بتوليد نسخة مضغوطة من قاعدة البيانات يومياً ويحفظها محلياً لمدة 7 أيام.

### التوصيات لرفع مستوى الأمان في النسخ الاحتياطي:
1. **النسخ الاحتياطي الخارجي (Offsite Backup):** تخزين النسخ الاحتياطية على نفس الخادم الذي يحتوي على النظام يمثل خطورة عالية (في حال تعطل الهاردوير بالكامل). يوصى بتعديل السكربت لرفع الملفات تلقائياً إلى مساحة تخزين سحابية مغلقة (مثل Amazon S3 أو Google Cloud Storage) بعد إتمام النسخ محلياً.
2. **تشفير ملفات النسخ الاحتياطي (Backup Encryption):** ملف النسخ الاحتياطي الناتج غير مشفر. يجب إضافة أمر تشفير باستخدام `gpg` أو `openssl` على ملف الـ `.sql.gz` قبل حفظه.
3. **تطبيق سياسة الاحتفاظ الدورية (Retention Policy):** الحفاظ على نسخ احتياطية كالتالي:
   - نسخ يومية لمدة 7 أيام.
   - نسخ أسبوعية لمدة 4 أسابيع.
   - نسخ شهرية لمدة 12 شهراً.

## 3. تحسين الاستعلامات والعمليات (Query Optimization)

### أ. مراقبة الاستعلامات البطيئة (Slow Query Logging)
تفعيل ميزة تسجيل الاستعلامات التي تستغرق وقتاً طويلاً للتعرف على المشاكل مبكراً. يتم ذلك عبر إضافة الأسطر التالية لملف إعدادات PostgreSQL:
```ini
shared_preload_libraries = 'pg_stat_statements'
log_min_duration_statement = 2000 # تسجيل أي استعلام يستغرق أكثر من ثانيتين
```

### ب. إعدادات التنظيف التلقائي (Autovacuum Tuning)
نظراً لأن جداول القراءات والفواتير ستشهد عمليات إدخال وتحديث ضخمة ومستمرة، يجب ضبط إعدادات الـ `Autovacuum` لضمان قيام قاعدة البيانات بتنظيف المساحات المتروكة وإعادة بناء الإحصائيات بشكل دوري لكي لا يقل أداء محرك الاستعلامات مع مرور الوقت.
