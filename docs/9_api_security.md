# تقرير وتوصيات أمان واجهات البرمجة (API Security Report)
**النظام المستهدف:** واجهات البرمجة الخلفية لـ SEMS (Node.js/Express API)  
**المرجع:** OWASP API Security Top 10  

---

## 1. أمان جلسات المستخدمين ورموز الوصول (JWT & Refresh Token Security)

### أ. سرية مفاتيح التوقيع (JWT Secret Key)
* **الملاحظة:** في ملف `auth.middleware.ts` السطر 28:
  ```typescript
  const decoded = jwt.verify(token, process.env.JWT_SECRET || 'secret') as any;
  ```
  وفي المتحكم `auth.controller.ts`:
  يستخدم النظام قيمة افتراضية صلبة `'secret'` و `'refresh_secret'` في حال عدم توفر متغيرات البيئة.
* **الخطر:** إذا تم إطلاق النظام بهذه القيمة الافتراضية، يمكن لأي شخص صياغة وتوقيع رموز JWT مخصصة وإدخال نفسه للنظام كـ `admin` (Authentication Bypass).
* **التوصية:** إزالة القيم الافتراضية تماماً وإلزام إيقاف تشغيل الخادم فوراً (Process Exit) في حال عدم توفر مفاتيح توقيع JWT قوية ومعقدة في بيئة التشغيل.

### ب. آلية تجديد الرموز وعمر التوكن (Token Rotation)
- حالياً، عمر رمز الوصول الافتراضي هو 24 ساعة.
- **التوصية:** تقليل عمر الـ Access Token ليكون ساعة واحدة فقط (1 Hour)، واستخدام الـ Refresh Token لتوليد توكن جديد تلقائياً. مع تفعيل آلية **Refresh Token Rotation** (إلغاء التوكن القديم فور استخدام التجديد لمنع هجمات سرقة الجلسة).

## 2. التحكم بالوصول للأجهزة وصلاحيات الأدوار (RBAC & Endpoint Protection)

### أ. تفعيل الفحص على كافة الواجهات
- يحتوي الباكيند على وسيط صلاحيات ممتاز `requirePermission` في `rbac.middleware.ts`.
- **التوصية:** يجب التأكد من عدم وجود أي واجهات عملات أو فواتير أو قراءات لا يمر الطلب فيها عبر وسيط المصادقة `authenticate` ووسيط الصلاحيات للحد من ثغرات **BOLA / IDOR** (Broken Object Level Authorization).

### ب. ثغرة التحقق من نطاق الفني (Zone Isolation Audit)
* **المشكلة:** عند أخذ القراءات أو مزامنة البيانات أوفلاين في `sync.controller.ts` و `readings.controller.ts`:
  النظام يقبل قراءة العداد طالما أن العداد موجود، دون التحقق مما إذا كان هذا العداد يقع في النطاق الجغرافي (Zone) المخصص لهذا الفني الميداني بالذات.
* **التوصية:** إضافة فحص برمجي في خدمة القراءات للتأكد من تطابق `zone_id` الخاص بالعداد مع `zone_id` الخاص بالفني الميداني المستدعي للطلب لمنع الفنيين من كتابة قراءات لعدادات خارج مناطق مسؤولياتهم.

## 3. أمان رفع الملفات وتطهير المدخلات (File Upload & Input Sanitization)

### أ. التحقق من الصور المرفوعة (Meter Reading Images)
في ملف `upload.middleware.ts`:
- **التوصية:** يجب عدم الاكتفاء بالتحقق من امتداد الصورة الظاهري، بل يجب تفعيل فحص البنية الحقيقية للملف (MIME-type validation) مثل `image/jpeg` أو `image/png` لمنع رفع ملفات بصيغ تنفيذية خبيثة قد تسبب ثغرات اختراق الخادم.

### ب. منع هجمات حرمان الخدمة عبر الطلبات الضخمة (Rate Limiting & Payload Limits)
- تم تفعيل Rate Limiter بشكل جيد في `app.ts` بمعدل 100 طلب لكل 15 دقيقة.
- **التوصية:** تخصيص معدل طلبات أشد لعمليات تسجيل الدخول وتغيير كلمات المرور (مثال: 5 محاولات كحد أقصى لكل 15 دقيقة) لمنع هجمات القوة الغاشمة (Brute Force Attacks).
